> 版本：v1.1 | 日期：2026-09-08 | 项目：IoT Web AI v11

## 一、业务逻辑

### 1.1 功能概述

场景自动化模块允许用户定义 **"当满足条件时，执行动作"** 的自动化规则。一个场景由两部分组成：

- **条件（Conditions）**：一个或多个设备单元的状态/值组合，条件之间支持 AND/OR 链式组合
- **动作（Actions）**：一个或多个操作，包括 control ON/OFF、data/text 设置、执行其他场景

### 1.2 条件系统

#### 六种操作符

| 操作符 | 中文名   | 适用类型     | 比较方式                       |
| ------ | -------- | ------------ | ------------------------------ |
| `>`    | 大于     | state / data | 浮点数值比较                   |
| `>=`   | 大于等于 | state / data | 浮点数值比较                   |
| `<`    | 小于     | state / data | 浮点数值比较                   |
| `<=`   | 小于等于 | state / data | 浮点数值比较                   |
| `==`   | 等于     | 所有类型     | 大写字符串比较（不区分大小写） |
| `!=`   | 不等于   | 所有类型     | 大写字符串比较（不区分大小写） |

**关键规则**：
- 数值操作符：双方转浮点数比较，任一方非数字则条件不成立
- 等值操作符：`String(raw).trim().toUpperCase()` 比较，ON/OFF 不区分大小写
- 设备值为 `undefined`、`null`、`OFFLINE` 时条件不成立

#### 条件链式组合（AND/OR）

```
条件1 --AND--> 条件2 --OR--> 条件3 --AND--> 条件4
```

评估算法：`result = logic === 'OR' ? (result || r) : (result && r)`

首条条件的 `logic` 字段忽略，前端点击逻辑徽章即可切换 AND/OR。

#### 值来源

优先级：**MQTT 实时缓存 (stateCache) > devices.json 静态状态 (getDeviceStatus)**

- MQTT 实时缓存：引擎订阅 `iot/device/+/state` 后实时更新
- devices.json 兜底：引擎启动初期 MQTT 缓存尚未填充时使用

### 1.3 动作系统

#### 四种动作类型

| 类型      | 中文名   | MQTT 主题                         | retain 策略                     | Qos  | 说明             |
| --------- | -------- | --------------------------------- | ------------------------------- | ---- | ---------------- |
| `control` | 控制     | `iot/device/{unitId}/control`     | lowPower→`true`；常在线→`false` | 1    | 发送 ON/OFF 指令 |
| `data`    | 数值设置 | `iot/device/{unitId}/datasetting` | 一律 `true`                     | 1    | 设置数值参数     |
| `text`    | 文本设置 | `iot/device/{unitId}/textsetting` | 一律 `true`                     | 1    | 设置文本参数     |
| `scene`   | 场景调用 | —（不发布 MQTT）                  | —                               | —    | 嵌套执行其他场景 |

#### retain 策略与文档一致性

| 动作类型 | 《设备定义说明文档》要求              | `server-auto.js` 实现       | 一致性 |
| -------- | ------------------------------------- | --------------------------- | ------ |
| control  | lowPower→retained, 常在线→不 retained | `isLowPowerUnit()` 动态判断 | ✅      |
| data     | 一律 retained                         | 固定 `retain: true`         | ✅      |
| text     | 一律 retained                         | 固定 `retain: true`         | ✅      |

#### 场景嵌套执行

- 最大嵌套深度：5 层（`MAX_SCENE_DEPTH = 5`）
- 循环引用防护：通过 `visited` Set 跟踪已执行的场景 ID，检测到重复则跳过
- 嵌套场景共用同一个 `visited` Set，确保整条调用链无循环

### 1.4 自动触发引擎

| 触发方式 | 实现机制                       | 是否检查条件 | 触发场景                    |
| -------- | ------------------------------ | ------------ | --------------------------- |
| 边沿触发 | MQTT 订阅 `iot/device/+/state` | ✅ 是         | 设备状态变化时实时评估      |
| 30秒兜底 | `setInterval(30000)`           | ✅ 是         | 场景刚创建/启用时条件已满足 |
| 手动触发 | `POST /api/scenes/:id/trigger` | ❌ 否         | 用户手动点击执行            |

**边沿触发去抖**：
```
prevSatisfied[sceneId] = 上一轮条件是否满足

条件: false → true  → 触发动作（边沿上升）
条件: true  → true  → 不触发（去抖）
条件: true  → false → 不触发
条件: false → true  → 触发动作（再次上升沿）
```

场景创建/编辑/启用/禁用/删除后重置 `prevSatisfied`。

### 1.5 场景生命周期

```
创建 → 启用(enabled:true) → 条件满足 → 触发动作 → 更新 lastTriggered
  |         |
  |         v
  |    禁用(enabled:false，不参与评估，prevSatisfied 重置为 false)
  |         |
  v         v
 编辑（重置 prevSatisfied，重新参与评估）
  |
  v
 删除（从 scenes.json 移除，清理 prevSatisfied）
```



### 1.6 触发历史

每次场景执行（自动触发、手动触发、定时兜底、场景嵌套调用）均自动记录触发日志，保存到 `data/scene-trigger-log.json`。

#### 日志条目结构

```json
{
  "id": "log_1725456789_a3f2",
  "sceneId": "scene_...",
  "sceneName": "高温开风扇",
  "source": "auto",
  "triggeredAt": "2026-09-08T10:30:00.000Z",
  "conditionSnapshot": [
    {
      "unitId": "keting-wdj-46716033_wdcgq-8684",
      "unitName": "温度传感器",
      "currentValue": "29.5",
      "operator": ">=",
      "conditionValue": "28",
      "satisfied": true,
      "logic": "--"
    }
  ],
  "actionResults": [
    { "action": "control", "unitId": "keting-shg-64771774_fengshan-0838", "value": "ON", "ok": true }
  ],
  "ok": true
}
```

#### 触发来源

| source             | 含义     | 触发场景                |
| ------------------ | -------- | ----------------------- |
| `auto`             | 自动触发 | MQTT 边沿触发           |
| `manual`           | 手动触发 | 用户点击触发或 API 调用 |
| `periodic`         | 定时兜底 | 30秒周期评估触发        |
| `scene:{parentId}` | 场景嵌套 | 被其他场景调用          |

#### 条件快照说明

- 每条快照记录了触发瞬间的**实时设备值**（`currentValue`）和**条件值**（`conditionValue`）
- `satisfied` 标记该条条件是否成立
- `logic` 标记与上一条条件的 AND/OR 关系（首条为 `--`）
- 条件快照在 `executeScene` 中通过 `evalSceneConditionsWithSnapshot` 采集
- 最多保留 200 条记录（`MAX_TRIGGER_LOG = 200`），超出后自动丢弃最旧记录
- 写入方式：原子写入，与 `scenes.json` 一致

### 2.2 双服务挂载模式

| 服务     | 文件                    | 端口 | 挂载方式                                                     | 功能                         |
| -------- | ----------------------- | ---- | ------------------------------------------------------------ | ---------------------------- |
| 配置服务 | `server-config.js`      | 6001 | `app.use(require('./server-auto').router)`                   | 场景 CRUD + 手动触发         |
| 控制服务 | `server-control-tcp.js` | 6002 | `const auto = require('./server-auto'); app.use(auto.router); auto.startEngine();` | 场景 CRUD + **自动评估引擎** |

**关键设计决策**：自动评估引擎仅在控制服务进程通过 `startEngine()` 启动，避免两个进程同时收到 MQTT 消息并重复触发场景。

## 三、功能及 API 说明

### 3.1 API 总览

| 接口                      | 方法   | 请求体   | 说明          |
| ------------------------- | ------ | -------- | ------------- |
| `/api/scenes`             | GET    | —        | 获取所有场景  |
| `/api/scenes`             | POST   | 场景对象 | 创建场景      |
| `/api/scenes/:id`         | GET    | —        | 获取单个场景  |
| `/api/scenes/:id`         | PUT    | 场景对象 | 修改场景      |
| `/api/scenes/:id`         | DELETE | —        | 删除场景      |
| `/api/scenes/:id/trigger` | POST   | —        | 手动触发      |
| `/api/scenes/trigger-log` | GET    | —        | 获取触发日志  |
| `/api/scenes/trigger-log` | DELETE |          | —清空触发日志 |

统一响应格式：`{ code: number, data?: any, msg: string }`

### 3.2 创建场景

```
POST /api/scenes
Content-Type: application/json
```

请求体：
```json
{
  "name": "高温开风扇",
  "description": "当温度超过28度时自动打开风扇",
  "enabled": true,
  "conditions": [
    { "unitId": "keting-wdj-46716033_wdcgq-8684", "unitName": "温度传感器",
      "unitType": "state", "operator": ">=", "value": "28", "logic": "AND" }
  ],
  "actions": [
    { "type": "control", "unitId": "keting-shg-64771774_fengshan-0838",
      "unitName": "风扇", "value": "ON" }
  ]
}
```

**校验规则**：
- `name`：必填，不能为空
- `conditions`：至少一条，`unitId` 不能为空
- `actions`：至少一条，`type` 为 `scene` 时 `value` 不能为空，其他类型 `unitId` 不能为空
- `operator` 不在合法列表中则默认 `==`
- `logic` 非 `OR` 则默认 `AND`

### 3.3 修改场景

```
PUT /api/scenes/:sceneId
```

请求体同创建场景。保留 `id` 和 `createdAt`，更新 `updatedAt`，重置 `prevSatisfied`。

### 3.4 删除场景

```
DELETE /api/scenes/:sceneId
```

从 `scenes.json` 移除，清理 `prevSatisfied` 缓存。

### 3.5 手动触发场景

```
POST /api/scenes/:sceneId/trigger
```

手动触发**不检查条件**，直接执行所有动作。场景嵌套调用时 `source` 标记为 `manual` 或 `scene:{parentId}`。

```json
{
  "code": 200,
  "data": {
    "ok": true,
    "sceneName": "高温开风扇",
    "results": [
      { "action": "control", "unitId": "xxx", "value": "ON", "ok": true }
    ]
  },
  "msg": "场景已触发"
}
```

## 四、操作运行步骤

### 4.1 启动服务

```bash
# 确保 MQTT Broker 已运行
node server-config.js       # 端口 6001
node server-control-tcp.js  # 端口 6002，含自动引擎
```

启动后控制台输出：
```
[场景自动化] MQTT客户端连接成功
[场景自动化] 引擎已启动，订阅状态主题: iot/device/+/state
[场景自动化] 引擎初始化完成（边沿触发 + 30秒兜底评估）
```

### 4.2 前端操作

**步骤 1：进入场景管理**
1. 浏览器打开配置页面
2. 点击顶部导航栏 **"场景自动化"** 标签
3. 查看场景列表（表格形式）

**步骤 2：创建场景**
1. 点击 **"＋ 创建场景"** 按钮
2. 输入场景名称（必填）和描述（可选）
3. 点击 **"＋ 添加条件"**：弹窗按设备位置和单元类型过滤，勾选单元后点击"添加选中"
4. 为每个条件设置操作符和条件值
5. 多条件时点击逻辑徽章切换 AND/OR
6. 点击 **"＋ 添加任务"**：选择动作类型和参数
7. 点击 **"保存"**

**步骤 3：管理场景**

| 操作      | 按钮                    | 效果                      |
| --------- | ----------------------- | ------------------------- |
| 启用/禁用 | 红色"禁用" / 绿色"启用" | 禁用后不参与条件评估      |
| 编辑      | "编辑"                  | 进入编辑器修改所有字段    |
| 删除      | "删除"                  | 确认后从 scenes.json 移除 |

**步骤 4：编辑场景内的条件/动作**
- 点击条件行右侧黄色"编辑"按钮 → 弹窗修改操作符、值、AND/OR
- 点击动作行右侧黄色"编辑"按钮 → 弹窗修改动作值

**步骤 5：查看触发历史**
1. 在场景列表页点击 **"📋 触发历史"** 按钮
2. 弹窗展示所有触发记录，按时间倒序排列
3. 每条记录包含：场景名称、触发来源标签、触发时间、条件快照、动作结果
4. 点击 **"清空"** 按钮确认后清除所有历史记录
5. 点击 **"✕ 关闭"** 或点击遮罩区域关闭弹窗

## 五、测试步骤及结果

### 5.1 条件评估

| 编号 | 设备值    | 操作符 | 条件值 | 预期  | 结果 |
| ---- | --------- | ------ | ------ | ----- | ---- |
| C-01 | 30        | `>`    | 25     | true  | ✅    |
| C-02 | 20        | `>`    | 25     | false | ✅    |
| C-03 | 25        | `>=`   | 25     | true  | ✅    |
| C-04 | "on"      | `==`   | "ON"   | true  | ✅    |
| C-05 | "OFFLINE" | `==`   | "ON"   | false | ✅    |

### 5.2 条件链式组合

| 编号 | 条件1 | 逻辑 | 条件2 | 预期  | 结果 |

grep "场景自动化" server.log

### 6.3 常见问题

| 问题             | 可能原因               | 排查步骤                                                     |
| ---------------- | ---------------------- | ------------------------------------------------------------ |
| 场景不自动触发   | 控制服务未启动         | 检查 `node server-control-tcp.js` 是否运行，日志是否有"引擎已启动" |
| 场景重复触发     | 双进程同时运行引擎     | 确认只有控制服务调用 `startEngine()`，配置服务不应调用       |
| 控制指令未到设备 | 设备离线或主题不匹配   | 检查 MQTT Broker 和 retain 标志，查看日志是否显示 `[retained]` |
| 场景列表页空白   | API 请求失败或 JS 错误 | 打开 F12 → Console 查看错误，Network 查看 `/api/scenes` 响应 |
| 添加按钮无响应   | DOM 元素未找到         | 已修复（`getElementById`→`querySelector`），清除浏览器缓存重试 |
| 编辑器数据丢失   | 校验失败或 JSON 损坏   | 检查 `data/scenes.json` 格式，查看保存时的 API 响应          |

### 7.3 设计约束

| 约束                        | 说明                                         |
| --------------------------- | -------------------------------------------- |
| 仅 control 类型参与离线检测 | state/data/text 设备不参与，但可作为条件判断 |
| 存储为 JSON 文件            | 非数据库，高并发场景需注意文件锁             |
| 双进程共享 scenes.json      | 原子写入保证一致性，但存在毫秒级读取延迟     |
| 引擎仅控制服务运行          | 两个服务都挂载路由，但只有控制服务启动引擎   |
| MQTT 懒加载                 | 手动触发时按需连接，引擎启动时必定连接       |

### 7.4 扩展建议

1. **时间条件**：支持基于时间的条件（如"每天 08:00"）
2. **延时动作**：支持动作间延时执行（如"等待 5 秒后执行下一条"）
3. **条件组**：支持嵌套条件组（如 `(A AND B) OR (C AND D)`）
5. **通知动作**：支持发送通知（Webhook、邮件等）
6. **WebSocket 推送**：场景触发时实时通知前端
